本模块是仓库的脚手架层，不承载业务代码，而是集中定义全栈工程的运行边界：
- `package.json` 通过 `engines.node >=22.12.0` 锁定 Node 版本，并区分运行时依赖（next、react、@supabase/*、framer-motion、recharts、zod）与开发依赖（typescript、vite、vitest、tailwindcss、eslint-config-next）。
- `next.config.ts` 在 Next.js 启动时注入全局安全响应头（CSP、COOP/COEP、Permissions-Policy、HSTS、X-Frame-Options），并通过 `typedRoutes: true` 启用路由类型生成；CSP 脚本策略在 development 允许 `'unsafe-inline' 'unsafe-eval'`，生产环境收紧为仅 `'self' 'unsafe-inline'`。
- `tsconfig.json` 使用 `moduleResolution: bundler`、`jsx: react-jsx`、`noEmit: true`，并通过 `paths.@/* → ./src/*` 提供路径别名；`next-env.d.ts` 由 Next 自动生成运行时类型。
- `vitest.config.ts` 将测试环境设为 `node`，按 `src/**/*.test.ts` 收集用例，并复用 `@` 别名。
- `eslint.config.mjs` 基于 ESLint flat config 组合 `eslint-config-next/core-web-vitals` 与 `types` 规则，忽略 `.next`、`coverage`、`next-env.d.ts`。
- `postcss.config.mjs` 接入 Tailwind v4 的 `@tailwindcss/postcss` 插件。
- `requirements.txt` 单独声明 Python 侧 `requests`、`beautifulsoup4` 的版本范围，配合 `.gitignore` 中的 `__pycache__`/`*.db*` 等条目形成 Node+Python 双栈隔离。
- `.gitignore` 同时排除 Node (`node_modules`, `.next`)、Python (`__pycache__`, `*.py[cod]`)、Supabase 客户端缓存及本地 SQLite 文件，但保留 `.env.example`、`.env.template` 作为环境变量模板。
