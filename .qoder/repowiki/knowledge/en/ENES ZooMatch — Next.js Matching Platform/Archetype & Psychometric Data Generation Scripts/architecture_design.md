Two parallel toolchains feed the `data/` directory:

- Python scripts (`scripts/generar_arquetipos.py`, `scripts/generar_catalogo_v2.py`, `scripts/recopilar_items.py`) are standalone CLIs with `main()` entry points that parse `argparse`, build JSON documents, validate them against invariants, and write output atomically via `tempfile.NamedTemporaryFile` + `os.replace`. They produce `data/arquetipos.json` (16 MBTI archetypes), `data/catalogo_arquetipos_v2.json` (61 animals × 55 colors), and `data/preguntas.sqlite` (staging + curated items).
- The TypeScript script `scripts/generate-synthetic-profiles.ts` is a library (not a CLI) imported by tests; it reads `data/arquetipos.json` and calls `src/lib/matching.cosineSimilarity` plus `src/types/*` to generate `SYNTHETIC_PROFILE_COUNT=500` deterministic profiles seeded by `0x5a4f4f4d`, then computes pair similarity distributions and calibrates the matching threshold.

Dependency direction: scripts → `data/*.json` (consumed by TS generator); the TS generator depends on `src/` matching engine. Remote fetching is isolated behind retry-backed `requests.Session` instances with explicit User-Agent headers and HTML/JSON content-type validation; all network paths fall back to embedded constants (`PERSONALIDADES_FALLBACK`, `ANIMALES_FALLBACK`, `FUENTES_APROBADAS`). Licensing is enforced at the pipeline level — IPIP is the only source marked `automatizable: True`; OEJTS is reference-only, and ZooMatch-original categories are local fallbacks.
