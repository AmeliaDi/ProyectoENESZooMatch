The module is organized as a standard Supabase migration tree under `supabase/`:
- `migrations/` contains timestamped, ordered SQL migrations. `202610220001_secure_matching.sql` establishes the v1 schema (`archetypes`, `profiles`, `quiz_items`, `quiz_responses`, `score_vectors`, `matches`) with the `public.app_role` enum, `private.touch_updated_at()` trigger, `private.is_admin(uuid)` helper, cosine-similarity match computation, and RLS policies granting read access to `anon`/`authenticated` while reserving write paths for `service_role` via `SECURITY DEFINER` functions.
- `202610230001_multidimensional_v2.sql` is explicitly additive (no drops of v1 tables) and introduces parallel v2 tables (`animals`, `colors`, `quiz_items_v2`, `profiles_v2`, `quiz_responses_v2`, `matches_v2`, `notifications`) plus RPCs (`submit_quiz_result_v2`, `compute_dual_matches`, `get_my_matches_v2`, `notify_matches_v2`, `get_my_notifications`, `mark_notifications_read`, `get_admin_dashboard_v2`). It reuses `private.cosine_similarity` from v1 and adds `private.dimension_badges_v2` for badge generation.
- `202610240001_matches_v2_explainability.sql` and `202610220002_admin_analytics.sql` extend the v2 schema with explainability and analytics support.
- `promote_admin.sql` is a one-off script (not a migration) that promotes an Auth user to `admin` role by inserting into `public.profiles` and `user_roles`.
- `seed.sql` / `seed_v2.sql` populate catalog tables (`archetypes`, quiz items, animals/colors) using `INSERT ... ON CONFLICT DO UPDATE` for idempotent seeding.

Dependency direction: v2 depends on v1 only for shared primitives in `private` (`cosine_similarity`, `is_admin`); v1 has no dependency on v2. All mutating operations go through `SECURITY DEFINER` functions; direct DML on business tables is revoked from `anon`/`authenticated`.
